# Noscari Baby 首次真实师徒实验

实验日期：2026-10-19；原始日志使用 UTC。软件：0.1.0a3。性质：单次真实外部助手教学试验，不是独立多教师复现。

## 结论

Baby 实际发出了求助请求；本会话的 Codex 助手读取请求后提供一条结构化建议；程序自己执行、验证并训练，随后在提前冻结的相关任务上改变了选择和结果。它的可训练状态确实受到本次经历影响。

但本次尚未证明“知道自己做不了才问”：它在尝试前就提问，教学任务的第一个菜单恰好包含目标，原有遍历一步即可成功。新规则在混乱分类下产生负迁移，规则记忆基线也取得相同总体效果。这些是实验结果的一部分，未换种子、重做教学或临时硬编码询问来掩盖。

## 任务、初态与真正的提问

任务是寻找降低音频嘶声的功能，菜单名称是现有语义词表之外的一个软件家族，预算 4 单位，无搜索渠道。初始方法模块只有遍历；求助选择器使用此前固定选定的 Round 2 clean/seed-0 训练检查点。其来源和文件哈希在 session.json 中。它不是完全无经验的白板，也没有在本次试验中从零学会提问。

它发出的原始问题如下（原始英语模板，未替它润色成更聪明的解释）：

> My current goal is audio:reduce-hiss-20780. I have opened 0 menu(s) without completing it, and have 4 operation units left. Search is unavailable. I do not yet have a learned semantic method for these labels. Could you teach me how to choose a relevant menu for this kind of task, so I can try it myself?

决策时已打开菜单数：0；求助耗费 1 单位，仍可自行尝试。当前候选评分：

| 候选 | 估计得分 |
|---|---:|
| ask | 0.629458 |
| traverse | 0.497640 |

选择来自可训练评分器在授权候选中的排序；没有“陌生就必须问”的强制分支。未训练参数对照在相同任务中选择遍历，没有发问。教师权限关闭时也不会询问。模板负责措辞；尚无学习生成问题内容或校准“我不知道”的元认知模型。教师可靠性 0.95 是实验情境假设，不是测得的助手可靠率。

## 第一条教学与执行

我的建议仅为：音频任务可先考虑 Sound desk；由 Baby 自己打开检查；失败则保留遍历，不把对应关系泛化为所有软件通用。没有提交菜单 ID、完整执行脚本、测试答案或权限。机器可读部分只有 audio → sound desk；解释原文完整保存在 teacher-reply.json。

这是当前会话中的真实助手回复，不是模拟器自动返回正确路径，也不是无人值守的商业 API 集成。开发者与教师均为同一助手，角色未达到严格独立盲法；不能夸大外部有效性。

程序实际执行轨迹：`ask:external-request-reserved → open:root-0:found`。总耗费 2 单位，成功。仅保存教学记录时参数摘要不变；显式 learn 后 L2 改变量为 0.256375283，首选方法从 traverse → 仅记录后 traverse → 训练后 semantic。原有 traverse 技能保留，参数回滚精确恢复初态。

教师不能提交 verified 标志。只有实际执行成功后宿主才生成经过验证的示范。此闭环更新原有 Axiom 的技能/方法排序模块；预训练恢复求助选择器在本次没有更新。它们仍是分开训练的模块，尚未合并成端到端自适应控制器。

## 未见相关任务结果

5 个任务种子组 × 3 种布局 × 20 任务 = 300 个任务，各组任务和预算相同。所有测试均禁止老师和搜索，不更新参数。任务种子组不是 5 次独立训练，所以不报告“5 次独立师徒实验”的置信区间。

| 策略 | 成功率 | 平均操作数 | 教师调用 |
|---|---:|---:|---:|
| traversal | 59.0% | 3.070 | 0 |
| same_record_frozen | 59.0% | 3.070 | 0 |
| rule_memory | 76.0% | 2.233 | 0 |
| learned | 76.0% | 2.233 | 0 |

同经验冻结对照保存相同示范，但不训练选择参数，保留原排序。rule_memory 则直接使用验证过的对应规则；它与 learned 达到相同表现。因此参数确有变化和行为后果，但没有证明该参数机制比直接规则检索更必要或更强。

| 分类 | 原遍历成功率 | 学习后成功率 |
|---|---:|---:|
| semantic | 56.0% | 100.0% |
| scrambled | 63.0% | 58.0% |
| legacy | 58.0% | 70.0% |

混乱分类中有 89% 的语义首选失败并回退，总成功率从 63% 降至 58%。这说明现有系统仍可能错误迁移，尚未学好规则的适用边界。保留旧方法降低了失败程度，但不能完全抵消错误尝试的预算代价。

此处回退沿用既有执行器的预置遍历逻辑；没有证明本次教学让它学会了回退时机。第二轮的可训练恢复模块仍是另一个实验模块。

迁移仅限同一个音频主题、同一标签家族的新功能名和新菜单布局。并未测试全新概念、任意软件、自由语言方法创造或开放世界技能。训练/测试任务 ID 无交集，评估参数不变。

## 失败和控制记录

教学后额外执行的诊断明确标为事后检查和合成故障控制，存于 first-teacher-controls；不纳入原冻结测试的统计结论。

- 同一教学任务的原遍历反事实：1 次操作成功；实际请教加尝试为 2 次。事后看并非必须求助，但单例也不足以判定一个事前不知目标位置的策略总体过度求助。
- 未训练选择器与教师拒绝授权：均未提问；无强制问答兜底。
- 教师不回复：请求保持 pending，只占用已预约的 1 单位，不继续循环或训练。
- 合成错误教师建议 audio → canvas：实际检查失败，未写入稳定技能或参数；保留的遍历随后完成任务，总计 3 次操作。该错误建议不是我本次的真实回答。
- 工程审查复现了中断后“旧参数配新回答”的日志缺陷，以及评估可替换检查点的问题；均在真实教学前用失败回归测试复现并修复。部分会话现在锁定，自动崩溃恢复仍未实现。

## 如何继续，以及 GitHub 的价值门槛

下一优先级是求助校准：用预先定义的可自行解决、信息不足、教师不可靠和求助昂贵任务，检验什么时候该试、该问、该放弃。统一求助与方法选择的反馈，让本次老师建议的实际成败也能更新以后的求助倾向；这同时回应此前动态反馈特征无增益的负结果。

随后接入受预算约束的本地文档检索，再考虑授权联网。检索应当是与尝试/请教并列的可选动作；来源内容仍为不可信证据，未经验证不写入稳定参数。检索目标是获取可验证信息，不是让外部 LLM 代替 Baby 执行所有决策。

“知道自己是谁、想做什么”先落实为可核查状态：稳定身份、当前目标、掌握方法、证据来源、失败与能力估计、权限和预算。当前请求已有静态身份标签、当前任务和方法状态；尚无可学习的持续自我模型。以后需要测试这些能力估计是否准确，并据此改变行动，不能只生成自我介绍。主观体验在本实验中没有得到检验。

当前已经具备研究 alpha 的公开价值：可安装代码、无密钥演示、真实参数改变、受控基线、原始失败记录与可替换教师接口。GitHub 不需要等待完整智能；我们的门槛是别人能复现并反驳具体结论。建议正式首发前再由独立的人通过接口完成一次新教学、跑干净环境/远程 CI，并完成发布文件隐私检查。当前并未向 GitHub/PyPI 发布。
