# Alpha 发布材料：凭据与隐私核验范围

2026-10-19。发布准备只涉及合成菜单研究数据、开发工具和已获授权的助手教学记录。
没有连接私人邮箱、联系人、聊天库或账户，也没有上传任何材料。

审查分为文件筛查、材料来源复核和打包核验，不能用一个“未命中”推断绝对无隐私风险。

| 范围 | 执行内容 |
|---|---|
| 当前源码、文档、实验 JSON/JSONL | 常见服务凭据、私钥、Authorization/带令牌 URL、个人主目录、邮箱及 `.env` 文件 |
| 历史 alpha 1–4 四份源码 ZIP | 逐文件读取压缩内容，包含历史实验/日志/请求/检查点；不只扫描最新版 |
| 历史 alpha 1–4 八个 wheel/sdist | 独立再次扫描，避免源码 ZIP 未含旧发行包而漏查 |
| 最终 a5 交付 | 新源码归档与发行包核验，以及发布成员清单；不包含虚拟环境、数据库或临时文件 |
| 来源与隐私人工复核 | 查看教师 request/reply/provenance、报告及实验生成方式；无私人用户教学、真实账号、私人对话全文或个人文件路径作为研究输入 |

当前工程没有 Git 仓库或提交历史；`git rev-parse` 返回 not a git repository。
“历史审查”指上列实际存在的本地归档，不声称检查了不存在的 Git 提交或远端数据。
未来导入其他 Git 历史时要重新检查全部对象；CI 的工作树筛查不能替代这一步。

扫描器不执行归档、不提取文件，对无法读取/损坏归档、超限和未知二进制明确报错，
不把未扫描内容称为通过。报告只保存相对位置、类别和哈希，不复制匹配出的敏感值。
`scripts/audit_release.py` 的嵌套归档、环境文件、损坏归档检查有回归测试。

旧合成 SQLite 工作数据库与虚拟环境不在发布范围内；可重放的公开经历位于 JSONL
和检查点中。`pip --report` 的原始本地路径、安装失败堆栈及开发临时文件保留在
本地 scratch，未放入发布包。公开的依赖清单仅保留官方分发 URL、版本、文件哈希
和许可证元数据。失败事件的脱敏说明见下面段落，不隐瞒发生过失败。

## 本轮工程失败与修正

- 扩展归档和数值复核工具前，五项测试先失败，最小实现后通过。
- 审查发现增量复现报告可能在尚未跑完时显示 `passed=true`。新增失败回归，改为
  只有 17 个预定检查全部完成并通过才能为 true；中断记录进度/下一个检查点及异常类型。
- 从 a4 升级 a5 的一次本地 pip 卸载触发 Windows 沙箱默认临时目录权限错误，后续
  导入因此失败；没有把这次运行计为通过。改用工作区临时目录，并重新建立另一套
  **全新**环境直接安装 a5，完整复现从头执行；原失败目录保留，未覆盖原结果。
- 审查指出会话回报设计中的随机后续行为不会利用信息，以及未来窗口长度含混；
  在开始下一轮实验之前修正设计。没有因此修改历史模型、轨迹或表现数据。

这是一项本地研究材料核验，不是生产安全认证、形式化隐私保证或全量依赖漏洞审计。
公开后接受研究者复核；如果发现遗漏，须停止公开相应材料并记录修正，而不是改写结果。
